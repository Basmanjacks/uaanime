## 1. `Gridi-1143/ani-ukr` (POSIX-shell, GPL-3.0, ціль — anitube.in.ua)

Найцінніше джерело: єдиний живий клієнт саме під наш перший сайт. Висновки про **механіку
сайту** (їх ми перевіримо на живій сторінці у Phase 0.5/1 — селектори виводимо самі):

- **Пошук** — POST на пошуковий endpoint DLE-двигуна (form-encoded: запит, пагінація,
  ~10 результатів на сторінку). Тобто не GET-параметр в URL. Для нас: `Provider.Search`
  має вміти POST; пагінацію в v1 можна обмежити першою сторінкою.
- **Список серій** приходить не з HTML сторінки тайтлу, а з **AJAX-endpoint'а плейлистів**:
  GET з news_id тайтлу + user hash, який видобувається з JS-змінної на сторінці тайтлу.
  Fallback — парсинг ініціалізації плеєра просто зі сторінки. Для нас: сторінка тайтлу —
  це два запити (HTML → hash, потім AJAX → плейлисти), і обидва мають бути у фікстурах.
- **Структура плейлиста ієрархічна**: тип (озвучення/субтитри) → студія/група → плеєр →
  серії. Це напряму підтверджує нашу модель `Release{Studio, Kind}` і те, що одна серія
  має кілька варіантів. Наш аналог їхнього fzf-вибору — резолюція переваг з build-brief §4.
- **Якості пакуються в один рядок** нотацією на кшталт `[720p]url,[1080p]url` всередині
  відповіді плеєра — треба парсити список варіантів, а не брати перше-ліпше.
- **Заголовки обов'язкові**: браузерний User-Agent, `Referer` на сторінку тайтлу,
  `X-Requested-With: XMLHttpRequest` для AJAX-викликів, Accept-Language з українською.
  Це підтверджує наше рішення нести `Headers` у `Stream` аж до mpv.
- **Відповіді містять `\uXXXX`-екранований юнікод** — треба декодувати до UTF-8, інакше
  українські назви студій перетворяться на кашу. Врахувати в парсері й у фікстурах.
- **mpv запускається з форматованим тайтлом** («назва — серія») — те саме робимо через
  `--force-media-title`.
- Історія переглядів — локальний файл-закладка. Підтверджує наш підхід, але в них немає
  позиції в секундах — лише номер серії. Наш resume з точністю ±5 с — реальна перевага.

Чого **не** переймаємо: fzf як залежність (у нас bubbles/list), відкриття плеєрів у
браузері, режим масового відкриття вкладок.

## 2. `vypivshiy/ani-cli-ru` (Python, GPL-3.0) + його бібліотека `anicli-api` (MIT)

Цінний як референс **архітектури**, не механіки українських сайтів:

- **Клієнт і парсери свідомо розділені в різні репозиторії.** Їхній ланцюжок контрактів
  `search → anime → episodes → sources → videos` — це майже 1:1 наші
  `Search → Title → Episodes → Sources → Extract`. Підтверджує providers.md §2; наша
  версія навіть строгіша (окремий `Extractor` за `Handles(embed)`).
- **«Ідентичність» клієнта має бути наскрізною**: user-agent (а в них навіть IP через
  proxy) під час екстракції і під час відтворення мають збігатися, інакше хост ріже потік.
  Для нас: заголовки, з якими екстрактор дістав URL, — ті самі, що піде в mpv. Один
  http-клієнт з одним UA на весь застосунок.
- **Посилання на потоки живуть ~24 години** — вони прямо попереджають не генерувати великі
  плейлисти наперед. Підтверджує наш інваріант «URL потоків не кешуємо».
- **Типізація озвучення в них неформальна** (описи «many/author/subtitles» у документації
  джерел, а не в моделі) — і це в них слабке місце. Наш формальний
  `Kind = dub | voiceover | sub | multi` у моделі — свідоме покращення.
- **У них немає персистентного стану взагалі** (кеш лише в пам'яті, історії немає).
  Це головна діра їхнього UX і головна причина існування uaanime: стан — наш диференціатор.
- Прапорці proxy/cookies/custom headers у v1 не переймаємо — це поза скоупом брифу.

## 3. Загальні висновки для нашого дизайну

1. Модель «провайдер повертає embed, екстрактор робить з нього потік» підтверджена обома
   референсами — залишаємо як є.
2. Найкрихкіше місце — не HTML сторінок, а **AJAX-плейлисти і hash-змінні** — тому фікстури
   мусять покривати і сторінку тайтлу, і відповідь плейлиста (уточнення до §8 providers.md).
3. Заголовки — частина даних потоку, не деталь транспорту. Губити їх між шарами — головний
   клас багів у цій ніші.
4. Resume з точністю до секунд і закріплена студія — фічі, яких немає в жодному з
   референсів. Ставка брифу на «стан» підтверджена.
