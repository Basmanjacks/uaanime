# План: гігієна TUI і екран серій

2026-11-17. Підстава — глобальний аналіз проєкту (того ж дня). Поза TUI переробляти нічого
не треба: lint 0, `go test -race ./...` зелений офлайн, додаткові лінтери не знайшли
дублювання; `httpx`, `store`, `remote`, `download`, `playback` лишаються як є.

## Що не так

1. **Статус ставиться вручну.** Трійка `m.status = …; m.statusKind = …; m.statusGen++`
   повторюється ~65 разів у 8 файлах `internal/ui`. Пропущений `statusGen++` — і таймер
   `statusExpiredMsg` старого повідомлення зітре нове.
2. **Клавіші описано двічі.** Обробка — у `handleKey` (`keys.go`, когнітивна складність 104),
   підказки й довідка — у таблиці `actions()` (`usability.go`). Вони вже розійшлися: `D`
   працює на історії, закладках і пошуку, але там не показується; на домівці показано
   `Esc назад`, хоча Esc там нічого не робить.
3. **Мертві рядки i18n**, що лишилися після переходу на `actions()`: `TuiHint*` (9 штук),
   `TuiMulti`, `TuiVoice`, `TuiMoreStudios`, `TuiActionRetry`. На трьох `TuiHint*` досі
   тримаються тести (`episodes_test.go:107`, `playing_test.go:171-173`,
   `settings_test.go:133`, `remote_test.go:187`).
4. **Екран серій зашумлений.** Кожен рядок повторює `Озв · 4UA · ще 6 озв · 3 саб  обереш
   студію` і сам собі суперечить: називає 4UA, а бейдж каже, що студію ще обиратимуть.

## Кроки

Сесія і виконавець на одній моделі, тож код пишу сам (правило «same model → write directly»).
Розмір — 4 кроки в одній підсистемі без схеми/грошей/доступу, тому `plan-review` не потрібен.

### Крок 1. `setStatus` / `clearStatus`

- `func (m *Model) setStatus(kind statusKind, text string)` — ставить усі три поля;
  `clearStatus()` — порожній текст, `statusInfo`, `statusGen++`. `success` стає обгорткою
  над `setStatus` (і перестає повертати завжди-nil `tea.Cmd`).
- Замінити всі ручні трійки. Збереження/відновлення статусу в `closeOverlay` — не трійка,
  лишається.
- Гейт: `go test ./internal/ui/`, `make lint`; `grep -n 'statusGen++' internal/ui/*.go`
  без тестів дає лише рядки в хелперах.

### Крок 2. Мертві рядки i18n

- Видалити перелічені константи. Тести, що на них спираються, перевести на `m.actions()` /
  `m.hint()` — перевіряти те, що реально бачить людина, а не мертвий рядок.
- Гейт: `go test ./internal/ui/ ./internal/i18n/`, `make lint`.

### Крок 3. Єдина таблиця клавіш

- Тип `binding{keys []string; key, label string; run func(Model, tea.KeyPressMsg) (tea.Model, tea.Cmd); when func(Model) bool; hidden bool}`.
  Для кожного екрана — один список; `actions()` будується з нього (рядки з `hidden` не
  показуються, `when` вирішує доступність, як зараз `len(m.cards) == 0` для `X`).
- `handleKey` = спільна прелюдія, порядок якої не міняється (скидання `quitArmed`,
  `ctrl+c`, фільтр списку, оверлей, `?`/`B`/`U`/`W`/Esc-pending), потім пошук у таблиці
  поточного екрана, потім — клавіша списку, як зараз.
- Виправити зафіксовані розбіжності: `D` показувати на історії, закладках і пошуку;
  `Esc назад` прибрати з домівки.
- Новий тест: для кожного екрана кожна показана клавіша обробляється (не падає в список
  «мовчки»), і кожна неприхована клавіша таблиці з'являється в довідці.
- `update` (складність 109) не чіпаємо: це switch за типом повідомлення, звичайний для
  bubbletea, і розбиття нічого не дає.
- Гейт: усі наявні тести `internal/ui` проходять без змін тверджень (крім тих, що
  фіксували розбіжності з п. 2 вище); `golangci-lint run --enable=gocognit` не показує
  `handleKey`.

### Крок 4. Екран серій: реліз у заголовку (варіант A, обраний 2026-11-17)

Рядок під назвою (замість одного з двох наявних порожніх рядків — висота списку не
міняється, правило «заголовок + список + підказка» тримається):

- є пін: `озвучка: 4UA (Озв) · ще 6 озв · 3 саб`;
- піна немає, кандидатів > 1: `озвучку не обрано · 7 озв · 3 саб · S обрати`;
- один реліз на весь тайтл: `озвучка: 4UA (Озв)`.

Лічильники — унікальні релізи по всьому тайтлу, `multi` рахується озвученням, як у `Pick`.
Наявний хвіст `· озвучка: X` із першого рядка заголовка переїжджає сюди.

Рядок серії — номер і лише відхилення від заголовка, у пріоритеті: стан завантаження >
позиція `12:40` / `переглянуто` > `лише саб` (наявний `TuiKindNotOutYet`) > інший реліз,
ніж у заголовку (`Озв · FutaShine`). Без піна рядок про реліз нічого не каже — Enter однаково
спитає студію. Хвіст `ще N озв · M саб` і бейдж `обереш студію` з рядків зникають
(`TuiPickWillChooseStudio` іде в заголовок або видаляється).

- Кольори лише з `theme.go`, нових немає; вузьке вікно — рядок під назвою обрізається
  справа, спершу втрачаючи лічильники.
- Гейт: `go test ./internal/ui/` (твердження про `meta` рядків серій в `episodes_test.go`,
  `studio_test.go` оновлюються свідомо — це і є зміна), `make lint`, tmux-смок на фікстурах
  `UAANIME_FIXTURES=1` при 100×30 і 72×22: «Фрірен» без піна, із піном, і тайтл з однією
  студією.

## Виконано (2026-11-17)

Усі чотири кроки зроблено; `make lint`, `make test`, `make build` зелені, tmux-смок на
фікстурах при 100×30 і 72×22. Відхилення від плану: висота списку на екрані серій **менша
на один рядок** — порожні рядки під заголовком виявилися частиною `chromeBase` і самого
списку, тож підрядок забирає рядок у списку (як нотатки оверлею ліміту). Підрядок є
завжди, навіть до приходу серій (`реліз: авто`), щоб список не стрибав. Попутно знайдено
й виправлено справжню ваду кроку 1: статус зміни налаштування (адреса пульта) міг
зникнути за 3 с від таймера попереднього «успіху» — тест
`TestSettingCycleStatusSurvivesOldSuccessExpiry`.
