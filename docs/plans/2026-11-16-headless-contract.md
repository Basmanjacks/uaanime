# ТЗ для uaanime — headless-контракт для домашнього сервера

2026-11-16, агент homeserver. Документ самодостатній: його (або окремий етап із розділу
«Промпти») можна віддати агентові в репозиторії `~/projects/uaanime` без доступу до homeserver.
Правила того репозиторію (`AGENTS.md`) мають перевагу над цим ТЗ; якщо вимога їм суперечить —
агент зупиняється й питає власника.

## Навіщо

На сервері `uaanime v0.6.3` працює без TUI: Telegram-бот викликає `search`, `episodes`,
`resolve`, `download --dir … --json` і сам читає службові файли (`.uaanime-title.json`,
`.<файл>.json`). Через прогалини CLI бот змушений вгадувати й дублювати логіку uaanime
(≈900 рядків у `bot/hsbot/uaanime.py`, `upgrade.py`, `quality.py`): сканує sidecar-и, вираховує
«улюблений реліз» за часом файлів, качає серію в тимчасову теку лише щоб дізнатися, який реліз
прийшов. Мета ТЗ — щоб uaanime сам чесно відповідав на ці питання.

## Рішення власника (16.11)

- Коли озвучки «своєї» студії ще немає, а іншої — є: брати будь-яку озвучку й лишати її.
  Тобто `download` без прапорців поводиться як зараз; явний вибір потрібен боту для заміни
  «субтитри → озвучка» й для ручних прохань.
- Plex-сумісні імена — так, окремим етапом (етап 5). Перейменування наявних файлів на сервері —
  окремий план homeserver, не це ТЗ.

## Вимоги

### Етап 1. Чесний `episodes` і машинні помилки

1. `episodes <id> --json`: кожен реліз отримує поле `playable` (bool) — чи є для цієї серії хоч
   одне джерело цього релізу, яке вміє хоч один екстрактор (`extractor.Find` за embed, без мережі).
   Наявні поля (`number`, `releases[].studio`, `releases[].kind`) не змінюються. Текстовий вивід
   позначає непідтримувані релізи (рядок через `internal/i18n`).
2. `episodes <id> --json --fresh` обходить кеш (`EpisodesFresh`). Без прапорця поведінка та сама.
3. Помилки під `--json` для всіх headless-команд: на stderr один JSON-об'єкт
   `{"error": {"code": "<код>", "message": "<той самий людський текст>"}}`; stdout порожній;
   код виходу як зараз. Коди щонайменше: `offline`, `provider`, `no_stream` (серії чи релізів
   немає), `host_unsupported` (релізи є, екстрактора немає), `release_unavailable` (етап 2),
   `quality_missing`, `cancelled`, `usage`, `internal`. Без `--json` — як зараз.
4. `uaanime version` (+ `--json` → `{"version": "v0.7.0"}`); `--version` — те саме, а не довідка.
5. `download … --json` додає до результату `id`, `episode`, `studio`, `kind` (те саме, що
   пишеться в sidecar).

Приймання: на фікстурі тайтлу, де в однієї серії один реліз лежить на непідтримуваному хості,
`episodes --json` дає для нього `playable: false`, а `resolve` його не повертає; тест на кожен
код помилки; `make test` і `make lint` зелені.

### Етап 2. Явний вибір релізу в `download` (і `resolve`)

1. `download <id> <серія> [--studio <назва>] [--kind dub|voiceover|sub|voiced]`:
   - `--kind voiced` — лише `dub` або `voiceover` (кращий за чинним порядком `Pick`); субтитри й
     `multi` не підставляються;
   - `--studio` без `--kind` — ця студія, тип за чинними правилами `Pick` для піна-wildcard;
   - задана пара/умова недоступна (немає на сайті, немає екстрактора або всі потоки мертві) →
     нічого не завантажується, код виходу 1, помилка `release_unavailable` (або
     `host_unsupported`, якщо реліз на сайті є, а екстрактора немає). Тихої заміни немає.
2. `resolve <id> <серія>` приймає ті самі прапорці й фільтрує кандидатів так само — щоб перевірити
   доступність без завантаження.
3. Порівняння `--studio` зі студіями сайту — за ключем з етапу 4 (регістр, гомогліфи).
4. Прапорці не змінюють піни, бібліотеку й `config.json` (як і зараз `download` — read-only
   щодо стану перегляду).

Приймання: `download X 5 --kind voiced --json` на фікстурі, де озвучка лише на непідтримуваному
хості, завершується `host_unsupported` і не лишає файлів (ані `.part`, ані теки); на фікстурі з
двома озвучками `--studio` бере потрібну; без прапорців вибір збігається з поточним (регресійний
тест).

### Етап 3. `downloads --json` — що лежить на диску

`uaanime downloads [--dir <шлях>] --json` (read-only, без мережі) друкує те, що знає
`download.SavedAll`:

```json
[{"id": "anitube:6108-psay", "name": "Псайрен", "folders": ["/…/Псайрен"],
  "episodes": [{"number": 6, "files": [{"path": "/…/Псайрен - 06 - Рідний Голос [Озв, 1080p].ts",
     "studio": "Рідний Голос", "kind": "voiceover", "height": 1080, "bytes": 393872408,
     "modified": "2026-11-16T19:09:58Z", "known": true}]}]}]
```

`known: false` — файл без достовірного sidecar (номер серії взято з імені). Теки без маркера
uaanime не показуються. Текстовий вивід — по рядку на файл.

Приймання: тест на тимчасовій теці з двома релізами однієї серії, файлом без sidecar і чужою
текою; вивід стабільно відсортований (тайтл за назвою, серії за номером, файли за шляхом).

### Етап 4. Назви студій

1. З'ясувати на свіжій фікстурі `anitube:3733-korolvstvo-2-sezon`, звідки береться студія `error`.
   Якщо це мітка сайту без справжньої студії — показувати резервну студію зі сторінки тайтлу, а
   якщо її немає — порожню студію (файл іменується без частини «студія», як уже вміє `Filename`).
   Якщо помилка розбору — виправити розбір. Регресійний тест на фікстурі обов'язковий.
2. Ключ порівняння студій: без урахування регістру й зі зведенням кириличних літер-двійників до
   латинських (А/A, В/B, Е/E, К/K, М/M, Н/H, О/O, Р/P, С/C, Т/T, Х/X, У/Y, І/I та малі
   відповідники). Ключ використовується для пінів, улюбленої студії, `--studio` і пошуку
   збереженого файла; показується назва завжди так, як на сайті (правило «назви студій не
   перекладаються» не порушується). Наявні sidecar-и й піни зі старим написанням мають
   і далі знаходитись.
3. З'ясувати, на якому хості лежали релізи з рядків 1–2 таблиці (Glass Moon, «Крісло-танк»,
   серія 5), через `--debug`. Якщо це новий відеохост, який віддає потік без авторизації, CAPTCHA
   й DRM, — додати екстрактор за `.agents/skills/provider-repair/SKILL.md` з фікстурами. Якщо
   ні — лишити `playable: false` і записати висновок у `docs/providers.md`.

### Етап 5. Розкладка імен для Plex

Прапорець `download --layout plex` (типово — чинна розкладка; нового налаштування в
`config.json` не додавати — ліміт 8):

- шлях: `<dir>/<Назва без сезону>/Season NN/<Назва без сезону> - SNNEMM - <Студія> [Озв, 1080p].ts`;
- сезон береться з назви тайтлу: «(2 сезон)», «2 сезон», «сезон 2», «Season 2», «S2» наприкінці
  назви → `NN = 02`, ця частина з назви теки прибирається; якщо сезону в назві немає — `Season 01`;
- sidecar і маркер лишаються; `downloads --json`, екран «Завантаження» й офлайн-відтворення
  знаходять файли в обох розкладках (маркер може лежати в теці сезону — рішення за виконавцем,
  але `Index` має знаходити файли на глибині двох тек);
- два тайтли-сезони однієї назви потрапляють в одну теку серіалу й різні `Season NN`; колізія
  з чужою текою без маркера розв'язується як зараз (`claimFolder`).

Приймання: табличний тест розбору сезону (щонайменше назви з таблиці вище, «Код Ґіасc:
Повстання Лелуша 2 (2 сезон)», назва без сезону, назва з числом, що не є сезоном — «Королівство
(2 сезон)» проти «86»); наскрізний тест `download --layout plex` на фікстурі; README описує
прапорець. Перевірку в справжньому Plex робить homeserver.

## Поза межами

- uaanime не видаляє й не перейменовує чужі файли: заміна «субтитри → озвучка», кошик, Plex,
  стеження за новими серіями й повтор невдалих завантажень лишаються в боті.
- Жодних обходів авторизації, CAPTCHA, DRM; жодних нових залежностей без обґрунтування.
- TUI не змінюється, крім місць, де цього вимагає етап 4 (ключ студії) чи 5 (пошук файлів).

## Що зміниться в homeserver після релізу

Описано в [плані бота v9](telegram-bot-v9.md), частина Б: встановлення нової версії поруч зі
старою, перехід бота на `downloads --json`, `download --kind voiced`, коди помилок і
`playable`; частина В — розкладка Plex і перейменування наявних файлів.
