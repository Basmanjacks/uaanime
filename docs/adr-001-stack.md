# ADR-001 — стек uaanime

Статус: **прийнято**, 2026-08-31. Після цього документа стек закритий; до питання не
повертаємось (Phase 0 брифу). Критерії оцінки — у порядку з брифу: простота встановлення
(одна команда, без рантаймів) → холодний старт < 100 мс → мало залежностей і легкість
підтримки парсерів → якість TUI-екосистеми → зручність агентної розробки.

---

## Що лишаємо

**Мова: Go, мінімум 1.25+ (змінено з «1.23+»).** Розглянув, лишаю Go, бо: один статичний
бінарник без рантайму (Python відпадає за критерієм №1 — потрібен інтерпретатор; shell, як
ani-ukr, не витягує надійний стан і resume), холодний старт тривіально < 100 мс,
крос-компіляція для GoReleaser з коробки, найкраща TUI-екосистема серед компільованих мов і
найзручніша мова для агентної розробки. Rust/ratatui дав би той самий бінарник, але
повільнішу ітерацію парсерів і більше церемонії без виграшу для цього класу задач.
Мінімальна версія піднята до **1.25**, бо go-директиви всіх трьох модулів Charm v2 —
`go 1.25.0` (перевірено 2026-08-31 у go.mod bubbletea, bubbles, lipgloss); заявлений у
первинному брифі мінімум 1.23 просто не зібрався б.

**TUI: Charm v2** (`charm.land/bubbletea/v2`, `charm.land/bubbles/v2`,
`charm.land/lipgloss/v2`). Розглянув, лишаю, бо: перевірено живцем — v2 реальний і активно
підтримується (bubbletea v2.0.9, серпень 2026), `bubbles/list` дає список із фільтрацією з
коробки (закриває весь наш UI «заголовок + список + підказка»), профіль кольору і ANSI-даунсемплінг
вбудовані. Імпорт-шляхи — тільки `charm.land/*`; `github.com/charmbracelet/*` — це v1,
його не пишемо. `AdaptiveColor` більше не існує — світлий/темний фон обирається явно через
`compat.HasDarkBackground`.

**HTTP/парсинг: `net/http` + `PuerkitoBio/goquery`.** Розглянув, лишаю, бо: сайти-цілі —
звичайний server-rendered HTML + AJAX-JSON (підтверджено prior-art), headless-браузер не
потрібен і заборонений; goquery — стандарт де-факто з CSS-селекторами, чистий `x/net/html`
зробив би парсери багатослівнішими без виграшу.

**Плеєр: зовнішній mpv через JSON IPC.** Розглянув, лишаю, бо: власний декодер — це
місяці роботи поза скоупом; mpv — стандарт ніші (обидва референси), IPC дає `time-pos`
для resume і `end-file` для завершення. Абстракція `Player` — одна реалізація у v1.

**Дистрибуція mpv.** mpv — системна залежність, яку `go install` не ставить. Рішення:
Homebrew-формула оголошує `mpv` залежністю (критерій «одна команда» виконується для
основного каналу); для `go install` та голого бінарника — `uaanime doctor` перевіряє
наявність mpv і друкує інструкцію встановлення. Відсутність mpv — зрозуміле повідомлення,
не стек-трейс.

**Сховище: JSON-файли з атомарним записом (tmp + rename).** Розглянув, лишаю, бо: обсяг
даних — сотні записів, це не база; JSON читається людиною і diff-ається; SQLite з cgo
заборонений брифом, а чистий modernc.org/sqlite — величезна залежність заради нічого.
Журнал прогресу — окремий крихітний файл, перезапис раз на 5 с (бриф §6).

**Пакування: GoReleaser → GitHub Releases + Homebrew tap + `go install`.** Розглянув,
лишаю, бо: стандартний шлях для Go CLI, нічого кращого немає.

**Залежності** — закритий список: charm.land×3, goquery, `golang.org/x/text`,
`stretchr/testify` (лише тести). Все інше — окреме обґрунтування в PR, за замовчуванням «ні».

## Що змінюємо відносно первинного брифу

1. **Go 1.23+ → Go 1.25+** — продиктовано Charm v2 (див. вище).
2. **Layout: тільки `internal/`, без публічного `pkg/anisrc`** (рішення користувача,
   2026-08-31). providers.md пропонував публічну бібліотеку як «запасний вихід»; це
   зобов'язання стабільного API з дня 1 без жодного реального споживача. Уся структура
   рішень (розділення provider/extractor, власний ID тайтлу, fallback-ланцюжок,
   contract-тести) зберігається — лише в пакетах `internal/provider`, `internal/extractor`,
   `internal/providertest`. Винесення в `pkg/` — механічний рефакторинг, коли з'явиться
   споживач.
3. **`Kind` уніфіковано: `dub | voiceover | sub | multi`.** Бриф §3 мав 3-значний варіант,
   providers.md — 4-значний. Дубляж і закадрове — різні речі на українських сайтах, і
   skill provider-repair їх уже розрізняє. Правило «не деградувати до сабів» стосується
   обох озвучених типів.
4. **`LocalTitle.ID`: не ULID, а опааковий стабільний ID без нової залежності** —
   unix-мілісекунди + `crypto/rand` у hex. Реальна вимога providers.md — «наш, назавжди»
   (стабільність + унікальність); ULID-спека (base32, монотонність, поведінка годинника)
   нічому тут не служить, бо ID не перетинає межі застосунку. Сортовність за часом — бонус,
   не гарантія.

## Відкинуті альтернативи

- **Rust + ratatui** — той самий бінарник, повільніша розробка, гірша сумісність із
  тренувальними даними агентів. Жодного виграшу за критеріями 1–3.
- **Python (шлях ani-cli-ru)** — найшвидші парсери, але провалює критерій №1: рантайм,
  venv, «одна команда» неможлива.
- **modernc.org/sqlite** — чистий Go, але тягне мегабайти коду заради даних, які вміщаються
  в один JSON.
- **fzf** — зовнішня залежність, що псує історію встановлення; `bubbles/list` фільтрує сам.
- **YAML-провайдери, плагіни, headless-браузер** — заборонені providers.md §10 і брифом;
  згоден з забороною.
